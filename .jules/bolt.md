## 2024-05-18 - Avoid heap allocations in high frequency packet callbacks and string arguments
**Learning:** String arguments in C++ embedded applications incur heap allocation and fragmentation overhead when passed by value. High frequency packet callbacks (`on_receive_packet`, `on_transmit_packet` in `RNode_Firmware.ino`) were heavily concatenating strings on every packet transmission/reception. Furthermore, pass-by-value strings for debug outputs (like `console_dbg` and `wifi_dbg`) allocate unnecessarily. However, some functions like `console_serve_file` modify the `path` string parameter internally and cannot be cleanly refactored to `const String&`.
**Action:** Always prefer `const String&` over pass-by-value `String` parameters for read-only accesses, especially in debugging/logging functions. Also, avoid constructing and concatenating large String objects inside high frequency callbacks or loops; stream the output linearly using multiple `print()` statements instead to conserve memory and cycles.
