## 2024-05-17 - Optimize SPI block transfers for LoRa Modems (SX126x/SX128x)
**Learning:** In Arduino/embedded environments, byte-by-byte SPI transfers (`SPI.transfer(buffer[i])`) inside a tight loop create massive function call overhead and block the CPU, heavily penalizing performance during high-speed radio operations. Using the block `SPI.transfer(buffer, size)` method is significantly faster as it leverages DMA or hardware FIFOs. However, for write operations, `SPI.transfer` modifies the provided buffer with the MISO response. Directly passing a packet buffer will corrupt it.
**Action:** When optimizing SPI transfers for non-destructive writes, do not modify the original buffer. Instead, implement a chunking mechanism using a small, stack-allocated temporary array (e.g., 32 bytes) and `memcpy` data into it before calling `SPI.transfer(temp_buffer, chunk_size)`. This prevents stack overflow compared to allocating a large array, while safely applying the block transfer optimization. For pure reads, use `memset(buffer, 0, size)` to pre-fill dummy bytes and perform the block transfer directly into the target buffer. Always add explanatory comments to such optimizations.
